# Autrifix API Contract Conventions

**Last synchronized with code:** 2026-08-18.

## General

The API is implemented with Django REST Framework. All routes are declared explicitly in
[`autrifix/api_urls.py`](../autrifix/api_urls.py) — there is no router and there are no ViewSets.

Base path: `/api/v1/`. OpenAPI 3 is generated by `drf-spectacular`:

| Path | Purpose |
|---|---|
| `/api/schema/` | OpenAPI 3 document |
| `/api/docs/` | Swagger UI (also `/swagger/`, and `/` redirects here) |
| `/api/redoc/` | ReDoc |

A preprocessing hook restricts the published document to `/api/v1/…` paths.

## Project-wide DRF defaults

Set in [`autrifix/settings/base.py`](../autrifix/settings/base.py):

| Setting | Value |
|---|---|
| Authentication | `rest_framework_simplejwt.authentication.JWTAuthentication` (only class) |
| Permission | `IsAuthenticated` |
| Pagination | `PageNumberPagination`, `PAGE_SIZE = 20` |
| Filter backend | `DjangoFilterBackend` |
| Throttles | `AnonRateThrottle`, `UserRateThrottle`, `ScopedRateThrottle` |
| Exception handler | `apps.core.exceptions.custom_exception_handler` |

## Authentication

`Authorization: Bearer <access>`. Tokens come from `/auth/login/`, `/auth/register/`,
`/auth/google/`, or `/auth/verify-otp/`, and are refreshed at `/auth/refresh-token/`.

Refresh tokens **rotate** and the previous one is blacklisted, so a client must persist the new
refresh token from every refresh response.

WebSockets authenticate with the access token in the **query string** (`?token=`), because
browsers cannot set headers on a WebSocket handshake.

Every endpoint below states its own permission. `AllowAny` is used deliberately on auth
endpoints and `/health/` only — `/services/nearby/` now requires authentication (ADR-014).

## Endpoint inventory

Legend: **C** customer · **P** provider · **A** any authenticated · **—** unauthenticated.

routes `/customers/*`→`/customers/*` and `/providers/*`→`/providers/*`. No aliases were kept.

### Agencies — `specs/017`

`/agencies/…` is the business seen from inside it; `/memberships/…` is the individual's own
place in one. An invitee is not yet a member, so their invitation cannot live behind an
agency-scoped lookup. Non-members get `404`, never `403`.

| Method | Path | Who | Notes |
|---|---|---|---|
| POST | `/providers/agencies/` | P | creator becomes the first active owner; `409` if already in an agency |
| GET PATCH | `/providers/agencies/{id}/` | member / admin | **`verification_level` is not writable** — an agency that set its own level would lift every member's (SPEC-017 REQ-3) |
| GET POST | `/providers/agencies/{id}/members/` | member / admin | invite by phone; `404` unknown number or customer, `409` already in an agency, `400` for `role=owner`. Throttled `20/hour` |
| PATCH DELETE | `/providers/agencies/{id}/members/{membership_id}/` | admin | role change or removal; `DELETE` on your own membership is "leave". `409` for the last owner |
| GET | `/providers/memberships/` | P | own memberships **including pending invitations**; unpaginated |
| POST | `/providers/memberships/{id}/respond/` | invitee | `{"accept": bool}`; `409` if already answered |

### Administration — `specs/012`

All gate on `IsAdmin` (`role=admin` or superuser). Everything else on the platform returns
`403` to an admin, and these five return `403` to everyone else.

| Method | Path | Notes |
|---|---|---|
| GET | `/admin/stats/` | Counts, including `jobs_auto_confirmed` — customers charged by timeout rather than agreement |
| GET | `/admin/users/` | `?q=` name/email/phone, `?role=`. Read-only; no credentials exposed |
| GET | `/admin/jobs/` | `?status=`. Read-only job history |
| GET | `/admin/verifications/` | `?status=` (default `pending`), **oldest first** |
| POST | `/admin/verifications/{id}/review/` | `{"approve": bool, "notes": str}`. `notes` is **required** when declining; `409` if already reviewed |

**Not exposed, deliberately:** private conversations (would widen SEC-GAP-17/34), the
verification document images (SEC-GAP-18 — reviewers use Django admin, OQ-012-I), and any
mutation of users or jobs.

## Authorization

Object-level authorization is required for anything owned by or assigned to a user
(`SECURITY.md`). The codebase implements this in three ways:

1. **Structural** — the object is derived from `request.user` and no id is accepted
   (`/me/`, `/customers/profile/`, `/providers/profile/`).
2. **Queryset scoping** — `get_queryset()` filters by owner, so a foreign id yields `404`
   (vehicles, requests, jobs, offerings, notifications, `/chat/`). This is the dominant and
   preferred pattern.
3. **Explicit check** — `JobChatConsumer._get_room_for_user` verifies participation directly.

As of 2026-08-17 every endpoint implements one of these. The three that previously implemented
none — `GET /chat/jobs/{job_id}/`, `POST /chat/jobs/{job_id}/messages/`, and `POST /reviews/` —
now use patterns 2 and 3 respectively.

When adding an endpoint, prefer pattern 2. Returning `404` rather than `403` for a
non-owned object is the established convention and avoids confirming existence.

Where a check cannot be expressed as a queryset filter, put it in a selector module
(`apps/chat/selectors.py`, `apps/customers/selectors.py`, `apps/providers/selectors.py`) so REST
and WebSocket transports share one definition.

## Status codes

Conventions actually in use:

| Code | Used for |
|---|---|
| `200` | reads, updates, logout, mark-read |
| `201` | register, create request/vehicle/offering/review, accept job |
| `400` | serializer validation; missing/non-numeric `lat`/`lng`; invalid Google token; bad OTP |
| `401` | missing/invalid token; bad credentials (`no_active_account`) |
| `403` | role gate failure (`IsCustomer` / `IsProvider` / `IsCustomerOrProvider`) |
| `404` | not found **or** not owned **or** not in a required state (e.g. request not `open`) |
| `409` | conflict with current state — see below |
| `429` | throttle scope exceeded; OTP per-phone cap |
| `503` | Google unconfigured; `google-auth` missing; SMS provider failure |

`403` is also raised via `apps.core.exceptions.VerificationRequired` when a provider is
authenticated and correctly-rolled but not yet **entitled** — currently only acceptance. Unlike a
bare permission failure it carries a structured body (`code`, `current_level`, `required_level`,
`verification_url`) so a client can render the next step rather than a dead end.

`409` is raised via `apps.core.exceptions.Conflict` and means *the request is well-formed but
conflicts with the resource's current state*. It is returned for:

- a lost acceptance race (another provider already took the request);
- accepting a request that is no longer `open`;
- an illegal job transition — the detail lists the permitted targets for the caller's role;
- cancelling a request that is already terminal;
- a duplicate review;
- a provider-only endpoint reached before the provider profile exists.

Re-sending a job's current `status` is an idempotent `200`, not a conflict.

Unhandled exceptions return `{"detail": "An unexpected error occurred."}` with `500` and are
logged — the handler does not leak stack traces, which satisfies `CONVENTIONS.md`.

## Error shape

DRF defaults are used unmodified: `{"detail": "…"}` for non-field errors and
`{"<field>": ["…"]}` for validation errors. There is no error `code` field, no envelope, and no
machine-readable error taxonomy. Clients must match on HTTP status plus field names.

## Pagination

`PageNumberPagination`, page size 20, with `?page=`. Applies to every `ListAPIView`.

Two list endpoints bypass it and are hard-capped at 50 results with **no truncation signal**:
`GET /jobs/requests/nearby/` and the `providers` array inside `GET /services/nearby/`.

## Filtering / search

`DjangoFilterBackend` is the configured default backend, but **no view declares
`filterset_fields` or a `FilterSet`**, so no query-parameter filtering exists anywhere.

Query parameters that *are* read:

| Endpoint | Parameters | Behavior on bad input |
|---|---|---|
| `/services/nearby/` | `lat`, `lng` (required), `radius_km` (default 50, max 500) | `400` for missing, non-numeric, or out-of-range — via `parse_coordinate_params` |
| `/jobs/requests/nearby/` | same | `400`, same helper |
| `/notifications/` | `unread` (`1`/`true`/`yes`) | ignored if unrecognised |

Notable absence: a customer still cannot filter jobs by status.

## Versioning

Version is a URL prefix only (`/api/v1/`). No DRF versioning class is configured, so
`request.version` is unavailable and there is no negotiation. Introducing `v2` today would mean
a second URL module.

## Compatibility

Changing a response field, a required request field, a route, a status code, or a state
transition can break the `autrifix-web` and future `autrifix-mobile` clients.

**Client-visible changes made on 2026-08-17** are listed in
[`IMPLEMENTATION-LOG.md`](IMPLEMENTATION-LOG.md). The breaking ones: `/services/nearby/` now
requires authentication, illegal job transitions now return `409`, and a request being worked on
reports `assigned` rather than `matching`.

Contract quirks that remain, and which cannot be changed casually:

- **Asymmetric `category`** — `ServiceRequestSerializer` accepts a UUID and returns a nested
  object, so a GET response cannot be replayed into a PUT.
- **`/requests/create/`** duplicates `POST /jobs/requests/` exactly.
- **`{"updated": n, "unread_count": n}`** from mark-read instead of the notification object, and
  `200` rather than `404` for an unknown id.
- **Unpaginated embedded collections** — `messages` on a chat room and the `/jobs/requests/nearby/`
  array are returned in full (the latter capped at 50).

Resolved quirks: customer-profile `latitude`/`longitude` are now always present (null when unset)
rather than conditionally omitted, and both chat transports now emit the same
`{"kind": "chat.message", "data": {…}}` envelope.

## When adding an endpoint

Per `CLAUDE.md`: update the corresponding spec under `specs/`, and test the success, validation,
authorization, not-found, and conflict paths. Prefer queryset scoping over post-hoc permission
checks, and declare the permission explicitly even when it matches the project default.
