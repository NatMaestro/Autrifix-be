# Spec-Driven Development

1. Identify the relevant spec.
2. Read product/domain/architecture documentation.
3. Inspect the current implementation.
4. Separate intended behavior from observed behavior.
5. Resolve or record conflicts.
6. Update the spec if the requirement is changing.
7. Create a minimal implementation plan.
8. Implement.
9. Test.
10. Review.
11. Record verification evidence.

Never fabricate missing requirements.
